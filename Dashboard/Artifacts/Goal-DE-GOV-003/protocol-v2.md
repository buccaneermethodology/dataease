# 逐任务评估协议 v2

## 观察目标与边界

本协议评估 DE-GOV-002 本地 SGE 指引是否减少可避免返工，同时保持验收质量。仅观察 DataEase；写入本 Goal 的 data/ 和 reports/，任务原始材料、被评估 Skill、全局和其他仓库保持只读。协议是前瞻观察设计，不是随机对照试验；观察结果只能支持有边界的关联与采用建议。

用户于 2026-10-14 将报告节奏更正为“每新增 1 个任务即生成评估报告”。从本次更正生效后新观察到的终态任务起，每个任务单独形成一份报告，并同时展示累计趋势；没有总样本数或日期截止。此前协议版本保留为历史。后续任何协议变更另起版本，禁止按结果删除不利样本。

## 纳入、分母与版本

- 从 data/state.json 的 started_at 起，登记本项目所有实际使用本地 SGE 的非平凡任务。主任务/Session 是计数单位；同一任务的重试、子 Agent、review 轮次、heartbeat 均不算新任务。task_id 稳定，thread_id 只是定位，不以聊天数代替任务数。
- 当前测量机制 setup、自身定时检查和报表工作、DE-GOV-001/002、琐碎只读问答列入排除清单，给出理由，不混入处理组。其他项目任务排除。
- 登记时固定 task_family、complexity_at_intake、risk、模型/推理档、实际 lane、Skill 文件摘要；未知写 null。复杂度按开始时约定：单一文档/局部改动为 small；多处但单模块为 medium；跨模块/权限/迁移为 large；不靠事后耗时倒推。
- 结束状态包括 completed、failed、cancelled。完成一次观察后计入批次，即使指标缺失。正在执行的任务保留为 right_censored，报告当前数量与已等待时长，不偷算完成耗时；中止/失败不丢弃。
- 样本稳定入册后，每个 observation_sequence 对应一个单任务报告，不合并相邻样本。报告编号按样本序号生成；迟到证据更新原任务 revision，追加修正版并保留旧版，不增加任务数。每日重复扫描以 task_id 和 source fingerprint 去重。
- 每个样本记录 intake 时真实 Skill 摘要。版本改变建立新 cohort，原数据保留；跨 cohort 的每任务报告必须分组描述，不能混算收益。仅知当前版本不能推断历史任务所用版本。

## 任务执行者的轻量采集

复制 task-record.template.json 到 data/tasks/<task_id>/v001.json，模板不是样本。仅保存时点、分类、计数和证据引用，不复制原始对话、源码、Token/密钥或业务数据。task_id 使用普通字母数字、下划线或短横线。

开始时登记 task_id、开始时点、范围类别、复杂度、风险、Skill 摘要与可定位来源。随实际发生记录以下原生时点；结束时一次核对并保存新 revision：

1. task_started_at：本任务授权后第一次实质执行；不能用创建聊天时间代替。
2. delivery_candidate_ready_at：主要交付首次可进入收尾的时间；不能等补齐所有收尾文件后才打点，以免隐去前移成本。
3. first_final_review_submitted_at：第一次明确提交最终审阅的时间；预审不混入。
4. terminal_receipt_at、final_readback_at：若适用，记录实际 Gate 与读回。无 Gate 的任务记 not_applicable 及原因；失败/中止记录 ended_at 和 outcome，不伪造 receipt。

可从实际工具/报告日志提取时间戳；提取后记录 source path/locator、SHA-256、event type、时间来源。观测时间 observed_at 与事件发生时间分开。mtime、手工估计和模型推断不进入主要耗时指标；无法恢复的值为 null，绝不补零。

记录治理区间（准备/必要审阅/收尾/包装返工/内联测量）、外部等待区间及可定位返工事件。无需逐命令打点或新增 reviewer；复用本任务已有独立验收。缺少区间证据时整体治理耗时为 null，仍可报告有证据的收尾墙钟。

测量记录放在本观察目录，不回写任务已经冻结或 Gate 绑定的材料。日志追加是本观察 Goal 的常规采集，不另建循环 Goal、不为每次记录复制全套收尾材料。采集不能延误真实任务修复；记录采集所用时间并纳入成本。

## 指标及算法

所有时间先转为 UTC；展示可用 America/Los_Angeles。区间必须 start <= end；同类并发重叠取并集，不把父子 Agent 时长相加。任一端点缺失则该派生值 null；负时长或越界保留为数据错误并剔除该指标，任务仍在分母。

| 指标 | 定义与用途 |
|---|---|
| 原始任务墙钟 | ended_at − task_started_at；不称主动工作时间 |
| 非外部等待墙钟 | 原始墙钟减显式外部等待区间并集；reviewer 和工具正常运行不是外部等待；未知等待不能主观扣除 |
| 收尾墙钟 | final_readback_at − delivery_candidate_ready_at；失败/中止单列，不虚构成功收尾终点 |
| 整体治理墙钟 | 所有治理区间并集长度，含必要 review、前置准备、收尾与内联测量；不能只缩短最后 Gate 阶段就声称整体更快 |
| 可避免包装返工 | 原文修正、缺写前字节、材料遗漏、错误路径、仅为更新旧 review 状态等原因引发的事件数；真实业务缺陷、用户范围变更、必要验证分别列出，不当作可削减项 |
| 最终审阅首轮通过率 | 首次完整最终审阅即允许收口的任务数 / 已提交最终审阅且结果可知的任务数；展示缺失和不适用分母 |
| Gate 首次调用有效率 | 首次实际调用产生 valid receipt 的任务数 / 实际调用且结果可知的任务数；valid CONTINUE 不等于任务完成 |
| 质量 | 独立审阅缺证阻断、未批准范围缩小、错误完成声明、实际严重回归的任务数与比例；unknown 不算零；独立审阅原有工作不为采集再做一遍 |
| 采集成本 | 任务内测量区间并集及 observer 每次运行墙钟，另列可用的同口径 token；报告/扫描本身均计入 observer 成本 |

每批与累计报告给中位数、最小/最大值、原始 n、有效 n、缺失 n 和失败/中止 n。n=5 不报精确尾延迟或“统计显著”。若给比例，同时显示计数；不把事件数当原子命令数，也不混合不同来源的 token 口径。

## 基线与收益计算

先登记 comparator，不依据结果挑旧样本。同 task_family、complexity_at_intake、risk、模型/推理档、必要验收范围、计时定义与工具环境的历史任务才可配对。差异或缺字段标注 unmatched；每个旧任务在同一批仅使用一次。多个合格旧样本按距观察开始最近优先，选择规则在查看结果前固定。若无历史主要指标，不用收尾阶段耗时冒充整体治理耗时。

旧安装任务 58:34.412 是诊断参考，模型/范围/计时不齐，默认不进入可比组；本次优化任务约9分钟也不作为前后对照。历史原始记录不足时保持未匹配。

对每个合格配对，计算 R = 1 − new_governance_wall / old_governance_wall（old > 0），汇报 R 的中位数及范围。另给每对秒差和本批 observer 总墙钟 / 5；扣除该摊销后的差值作为净收益参考。内联采集已含在 new_governance_wall，不能再扣一次。累计 observer 成本包含空扫描和出报告，用 run_id 去重并在两个批次间只分摊一次；到当前报告的未分摊成本单列。一次性测量机制 setup 成本及可知的优化实施成本另列，不当作任务样本；累计节省是否覆盖这些成本只在有足够可比证据时计算，缺成本或缺对照则回本结论为 unknown。

收益仍为观察性差异；模型变化、任务难度和执行熟练度可能影响结果。不为取得对照回退真实项目 Skill，不自动发起额外任务或付费实验。需要因果结论时另定义隔离复演/随机实验范围。

## 预先固定的决策标准

以下百分比是试运行的实用判定阈值，不是统计显著性或保证收益：

- 质量红线：任一经证据确认的错误完成声明、未批准范围缩小或严重回归，立即通知并出风险说明；建议定位/调整，不能自动回滚。计时更快不能抵消质量红线。
- 数据充分：单任务报告如主要时间点可用且质量结论可知，可报告该任务层面的事实。效率量化仍要求至少5个同口径可比配对；未达到时报告“量化收益证据不足”，并呈现本任务与累计趋势。需连续两个新任务报告均支持同一保留结论，且各自的累计证据满足原量化门槛，才可建议“重复观察支持”；不把单任务波动当作稳定效果。
- 暂支持保留：配对整体治理墙钟中位下降至少20%，摊销观察成本后的中位秒差仍为正，无质量红线且质量阻断率未升高；全任务墙钟未出现无法解释的20%以上中位恶化。记录内联采集时间目标中位<=60秒且占任务墙钟<=5%；超出则优先调整测量机制。
- 两个连续且各自新增一个样本的报告均满足上项，才建议“继续保留，已有重复观察支持”，仍不称因果证明；每份报告都必须包含当前新增样本，并给出截至该样本的累计证据。
- 若同口径中位恶化>=20%或可避免返工上升，先标“需要调查/调整”；连续两批重复或出现质量红线才提出具体规则调整/回退建议。任何更改 Skill 须形成单独授权任务。
- 介于阈值之间报告“收益不明显，继续观察”；缺对照不能据绝对时长宣布保留理由为效率收益。

## 每日 observer 的操作顺序

1. 读 data/state.json、data/census.json 与上次已处理 source fingerprints。先快速检查 Dashboard/Sessions.md 与已登记任务记录是否有新增；不每轮全文重扫历史包。
2. 按项目明确身份补充只读任务来源：优先项目 artifacts 和已有 task/thread ID；必要时 list_threads/read_thread，只读取已确认属于本项目的记录，不给其他聊天发消息。不扫描全机对话库、不采集无关业务内容。
3. 新任务登记进 census；终态未定保留进行中；终态已知则生成一个观察序号。证据不足记录 null/unknown，不能把“没有看到”当作不存在。索引截断/工具不可用记 coverage_unknown，不能声明发现了所有任务。
4. data/tasks/<id>/vNNN.json 追加修订；已有 revision 不覆盖。单一 observer 写 census/state/report，任务执行者只写自己的记录目录；更新前检查 state revision，冲突重读重算，不覆盖并发新数据。用同目录临时文件加原子替换写派生 state；历史任务/报告不重写。
5. 每发现一个新终态任务，先冻结 report-NNN-inputs.json（单个任务ID、revision、来源摘要、cohort、排除/缺失和成本），再生成 report-NNN-v001.md。报告同时列该任务与累计结果；没有比较证据也按期出报告。修订报告保留原版并说明更正理由。
6. 记录 run_id、started_at/ended_at、已消耗时间及可用同口径 token。没有新增样本不产生无意义的新任务记录，静默保存必要 cursor/cost。报告生成失败不得先标 published。
7. 只在新一轮报告、已确认质量风险、或有实际任务却持续采集失败需用户行动时通知；无变化保持安静。重复同一 report_id/risk_id 不重复通知。

自动调度必须读回确认创建；创建成功不证明未来必然触发。本地文件任务依赖电脑与桌面应用可运行。若连续3次实际新任务均无法采集关键字段，发一次“采集机制需要调整”提醒；没有新任务不算失败。


## v2 生效边界

报告频率更正于 2026-10-14 生效。此时已有 observation_sequence 1–2，均在原五任务规则下登记，未达到原报告触发点；新节奏从下一个新终态任务（sequence 3）起逐任务执行。历史已观察任务保留在累计趋势中，不追溯伪造成更正前已发布的逐任务报告。
