# SP-001 实现设计

Goal/contract为范围权威投影。源代码+有效规范为产品依据；docs/Dashboard仅线索。所有中间件放SP-001，kb只包含知识JSON、schema、长期工具与投影。
先盘点建立事实分母，再以图表链验证最小生产链；随后按数据接入/建模、图表/编辑器、分享/权限/运行分域提取。每项候选事实需文本、类别、路径、符号/行区间、源摘要、适用条件；按能力汇总输入输出、前后条件、不变量及异常。关系需独立证据，不按命名匹配。
JSON schema严禁额外字段并区分事实、能力、关系；正式事实仅implemented/configured/normative，tested不用作静态默认状态。待澄清归SP。检查器只验证结构与来源完整性，不宣称语义正确。反例见contract-v1.json。
长期工具无第三方新增依赖优先；已有jsonschema可用时做标准schema验证。生成采用排序、UTF-8与固定格式，不把当前时间写进渲染输出。记录source时间而不是每次生成时间。
Builder不可修改goal/contract/原始意图；独立预审后绑定准入。范围/基线/合同变化保留旧版并重新审查。用户明确授权本地写入但不授权Git发布。
