## 本次源码观察

- `core/core-frontend/src/store/modules/user.ts` 将 token、uid、oid、proxyInfo 等写入 `wsCache`；`setUid` 在调用标签更新其 Pinia state，并经 `useCache()` 默认写入按 pathname 前缀分区的同源 `localStorage`；相同前缀的标签共享持久缓存，不等于各标签 Pinia 自动同步。`clear()` 清理用户键并清理平台绑定、图片缓存，但源码没有本功能专用的身份 generation 字段或跨标签剪贴内容失效协议。
- `core/core-frontend/src/utils/logout.ts` 调用 user/permission/interactive Store 清理、reset 和路由处理；可作为当前标签登出入口证据。它没有证明服务端撤销、其他标签失效先后、旧标签并发写入阻断或用户切换时旧 payload 不可复活。
- `core/core-frontend/src/utils/resourceImages.ts` 有 `storage` listener，身份相关键变化时清理图片缓存；该用途仅为图片缓存，不是 S02 剪贴载荷的 authority。本轮绑定读集未找到 S02 专用跨标签 generation 协议；这不构成全仓库不存在证明。
- `core/core-frontend/src/hooks/web/useCache.ts` 使用浏览器缓存封装；当前静态证据不能据此推导浏览器锁、CAS、顺序一致性或可靠的身份撤销。
- `pure-guards.ts:isTtlValid` 是两个数值输入间的有限 TTL 比较器。它不提供服务器时间、单调时钟、签名到期凭据或回拨检测；运行通过也不能证明时钟可信。

以上是当前工作树源码定位，不等于完整认证契约或运行期行为。本轮绑定到的 `SP-005/S02-S09_EntryPacket.md` 存在，S02/F01 状态为 `CONDITIONAL`；它是候选入口资料，不是已满足的准入或实施批准。当前资料没有证明真实多用户权限环境可用，也未提供可访问的权限模块来源；本轮未读取专有 XPack，不以 standalone/admin 替代。

## 候选生命周期约束

1. 复制内容必须绑定可验证的当前登录会话代际；仅比较 uid 不足以区分 U→V→U。会话 generation（一次认证会话/登录代际）与 permission version（权限变更版本）是不同维度；必须由真实认证/权限契约说明两者是否存在、各自何时变化，以及撤权何时可被观察。当前不假设权限变化必然更换整个会话 generation。
2. 登出、账号切换、组织/代理上下文变化或权限撤销后，旧授权绑定的载荷不得继续被批准读取/提交；这不预设权限版本变化必须轮换整个 session generation。认证会话代际、权限版本及资源上下文是否分别变化、撤销何时可观察，必须由真实契约确定。跨标签通知只能触发重新读取/清理，不能自身作为授权凭证。
3. 刷新与读取不得延长创建时长；TTL 比较的输入必须来自同一冻结 authority，异常值、未来创建值、时钟不可用或身份 authority 不可验证时 fail closed。
4. 浏览器 Date/本地持久化时间不能单独证明可信时间或抵抗回拨；任何“服务端会话代际”“服务端时间/到期凭据”方案均需先由真实权限模块/API 契约证实。
5. U→V→U、旧标签延迟事件、登出后刷新、撤权后仍打开标签、并发旧标签写入以及时间回拨/跳前、休眠恢复、刷新后过期边界都必须进入后续真实身份环境的验证矩阵；当前均未运行。

## 待审查场景与候选观测 oracle

以下为待审查的场景候选，仍不是冻结测试合同。需要真实 authority 返回及约定的观察接口；缺失时结果为 `NOT_RUN / BLOCKED`，不能以 mock 或纯 helper 通过代替。统一观察目标配置 revision、预览/过滤查询调用数、成功提示、载荷身份/权限版本与来源时间；不得只用 UI 文案判定。

| 场景 | 初始状态与有序事件 | authority 结果 / 候选 oracle | 观察点 |
|---|---|---|---|
| ID-01 U→V→U | U 会话复制载荷 P；U 登出；V 登录并尝试读取 P；V 登出；U 以新会话登录再尝试读取 P。 | 若服务端给每次认证会话提供不同 generation，则 P 绑定旧 generation 必须拒绝；只凭 uid 相等不得放行。 | 目标 revision 不变、预览与过滤查询均为 0、无成功提示；记录当前 generation 与 P 的绑定值。缺 generation authority 时 blocked。 |
| ID-02 迟到旧写入 | 标签 A 在会话 g1 开始复制；发生登出/新会话 g2；随后 A 的 g1 复制响应最后到达。 | 旧 g1 写入不得覆盖较新状态或复活无效载荷。要断言该顺序，需要 authority 提供可比较版本或等价 fencing；浏览器事件通知不足以证明。 | 载荷 revision/generation、写入顺序、失败结果；旧操作不得成功提示。若没有 fencing 契约则不实现/不验收该保证。 |
| ID-03 prepare 后撤权 | 有编辑与数据访问权的用户开始 prepare；管理员撤销其中必要权限；用户继续确认/commit。 | commit 前以真实权限 authority 重验；撤权后应拒绝，恢复权限不自动使旧 prepare/载荷重新有效。 | 目标 revision 不变、无新预览/过滤查询、无成功提示；须用真实编辑/只读账号及可复核撤权记录。当前 BLOCKED / NOT_RUN。 |
| TIME-01 TTL 边界与重复读取 | 固定不可变创建时刻 c；分别以 c+1799999、c+1800000、c+1800001 尝试；中间重复读取/刷新。 | 纯数值合同为前者有效、后两者过期；重复读取和刷新不改变 c。此结果只验证比较边界。 | 记录 authority 返回时间、创建/到期值、payload 状态与纯比较器结果；没有可信时间协议时不得声称真实 30 分钟。 |
| TIME-02 时间异常与延迟样本 | 固定载荷创建后依次注入回拨、跳前、未来创建值、非有限值、过期/迟到响应及休眠恢复。 | 只有协议定义 freshness、误差、会话绑定和异常处理后才可执行；不可信/无效样本应 fail closed，不得续期。当前规则是候选，待 authority review。 | 载荷创建时刻不能被重置；拒绝时目标、预览/查询均不变；分别记录时间请求标识、样本顺序和有效性。 |

## r004：Review r002 指定的候选场景补充（未冻结）

本节将原五项场景拆成独立初态、顺序与按本次操作归因的观察量，供后续 authority review 和独立复核。它们仍是候选 oracle；缺少可验证 authority 或环境时一律 `BLOCKED / NOT_RUN`。计数使用操作前后的 delta，避免将页面启动查询归入本次操作，也不得删除原合同要求的成功预览。

| 场景 | 独立初态与有序事件 | 候选结果 | 本次操作的 oracle |
|---|---|---|---|
| ID-01A 跨用户恢复 | U 会话 g1 创建载荷 P → U 登出 → V 登录尝试读取 P → V 登出 → U 以新会话登录尝试读取 P。 | V 及新 U 会话均不得因 uid 相同重新获准使用 P；缺真实 generation/授权绑定时保持 blocked，不能退化为只比 uid。 | 拒绝操作引起的目标 revision、预览/查询新增调用和成功提示均为 0；原目标保存状态不变。 |
| ID-01B 登出后旧标签恢复 | 标签 A 持有 g1 与 P → 登出 → 标签休眠/离线 → 浏览器刷新或恢复 → A 尝试读取 P。 | 恢复时重新验证当前 authority；旧缓存不得单凭本地存储自动变成有效。 | 记录恢复前后身份绑定和 payload 状态；拒绝时本次操作新增查询为 0、目标状态不变。在线、离线及网络恢复分别独立运行。 |
| ID-02A 同会话新旧复制竞争 | 同一会话内 A 开始复制 P1 → B 开始较新的 P2 → 以 B 后 A 的顺序完成响应。 | 若合同要求最新意图胜出，P1 不得覆盖 P2；排序/fencing 机制必须由真实存储契约定义。 | 记录两次操作 ID、完成顺序、持久化版本；最终有效载荷必须与冻结的赢家规则一致。无可信顺序/fencing authority 时不冻结。 |
| ID-02B 身份切换迟到写 | A 在 g1 开始复制 → 切换到 g2 → g1 的成功响应最后到达。 | g1 写入不得覆盖 g2 当前状态或复活 P。 | 旧请求不得产生成功提示或改变当前身份绑定载荷；本次拒绝新增查询为 0。 |
| ID-02C 通知/存储故障 | A/B 标签并发 → 丢失或乱序广播/`storage` 通知；另以 storage 写入拒绝、quota error 为独立初态重跑。 | 通知仅是失效提示；不能用通知到达推断授权。读写失败按协议 fail closed，恢复后显式重读 authority。 | 每个故障初态独立记录当前身份、持久化版本、读写结果；无有效证据时 P 不得被消费或复活。 |
| ID-03A 撤权和恢复 | 有权用户 prepare → 管理员撤销必要资源/编辑权限 → 用户 commit → 管理员恢复权限 → 再执行一次新操作。 | 撤权后 commit 必须拒绝；恢复权限不会自动重活化撤权前的 prepare/P。权限检查与 commit 原子边界由真实后端契约确定。 | 撤权 commit 的目标 revision、预览/查询增量为 0、无成功提示；恢复后的新操作按当前 authority 独立判定。 |
| ID-03B 只读/无数据权/上下文变更 | 分别以只读、无数据访问权限起始；以及组织切换、代理上下文切换起始，尝试 source-read 与 target-commit。 | 未授权读取/提交均拒绝；上下文改变后旧绑定不能继续授权。 | 对每类身份与入口分别记录服务端拒绝、目标 revision、查询/预览增量；仅 UI 隐藏不作证据。需要真实多用户环境。 |
| TIME-01A 只读及 TTL | 使用固定创建样本 c，分别在 c+1799999、c+1800000、c+1800001 发起读取；读取后重复读取/刷新，仍使用原 c。 | 纯比较器边界仅为数值候选：首例有效，后二例过期；读取/刷新不得改变 c 或 expiresAt。 | 只读读取自身不得新增分析查询；过期粘贴不得新增预览/过滤查询或改变目标；所有数值相对可信时间仍待协议。 |
| TIME-01B 成功粘贴 | 以真实有效、未过期、身份/权限均匹配的载荷执行一次粘贴。 | 按原合同允许成功路径，并保留其规定的预览行为；不可用“失败无副作用”错误要求成功路径查询为零。 | 记录本次调用前后 query/preview delta，目标 revision、payload createdAt/expiresAt；成功后创建/到期绑定不得延长。次数需由冻结合同精确定义。 |
| TIME-02A 异常样本隔离 | 每个初态只注入一种：回拨、无法判定的前跳、未来创建值、非有限值、迟到响应、休眠恢复。每种从新载荷/新会话重跑。 | 无效/过期样本按 fail-closed 候选；“有效前跳”需与不可信时间样本区分，不能预设一律拒绝。 | 每例单独记录 request id、样本顺序/freshness、payload 时间、目标状态及本次查询增量；拒绝不得续期。 |
| ID-04 登录/刷新迟到响应与重放 | g1 发起登录/刷新 → 切到 g2 → g1 响应迟到；再分别重放已消费响应和重复 commit。 | 旧身份响应不得覆盖新身份；重放按真实服务端幂等/nonce/版本合同拒绝或返回幂等结果。 | 记录身份版本、响应 request id、一次性凭据/幂等键（若合同存在）、目标 revision 与请求增量；无服务端契约时不能声明抵御重放。 |

所有拒绝型场景均观察：本次动作前后已保存目标状态、payload 是否仍可消费、预览/过滤/提交调用 delta、成功提示、服务端 authority 响应及身份/权限/时间版本。`delta=0` 只用于拒绝操作，不用于原合同要求的成功预览。候选成功路径须断言 `createdAt` / `expiresAt` 不因读取、刷新、重试而改变。所有案例需要先冻结 authority 和计数定义，再交独立审查；本轮不新增/关闭 Goal 产品义务。
