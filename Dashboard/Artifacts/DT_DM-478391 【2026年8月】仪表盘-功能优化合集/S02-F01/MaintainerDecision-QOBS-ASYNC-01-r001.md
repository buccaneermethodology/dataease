# QOBS-ASYNC-01 维护者裁定 r001

维护者选择：**重新请求核对 C**。

## 裁定范围

触发场景为：枚举请求发出后，用户将单选值改为 C；该请求成功返回且不含 C，同时当前组件身份、raw、设计 revision 和请求身份仍匹配。

- 首次成功响应缺少 C 时，保留用户选择 C，不让首次响应清除/回填运行值或改写设计配置；发出一次额外枚举请求核对 C。
- 核对请求完成前保持 loading。首次请求加核对请求总计两次枚举请求；不因该处理额外触发过滤条件查询/刷新。
- 核对成功且包含 C：以核对结果更新 options，保留并显示 C 为有效值；结束 loading。
- 核对成功但仍不含 C：以核对结果更新 options，保留并显示 C 为无效值，不清除 C、不改写设计配置；结束 loading。
- 核对请求失败：保留 C 和此前已接受的 options，将有效性标为未核实；失败定稿后结束 loading，不再自动重试。
- 所有响应仍受当前对象身份、raw、设计 revision、token generation 和请求身份门控；过期响应不得写入。

此裁定只关闭该明确竞态的产品语义歧义，不扩大功能范围，也不解除 S01 Entry Packet、真实权限隔离环境、可信 RED、独立预审或精确 Builder admission 等其他门槛。来源为用户在本任务线程对 QOBS-ASYNC-01 的直接回复（2026-10-18，用户原话已选择“重新请求核对 C：核对后结束 loading，多一次枚举请求；若 C 不存在则显示为无效”）。
