# 修复委派顺序偏差

Coverage修复轮：主代理先发送包含扩展备份写范围的修复指令，随后才生成并发送修复卡片。Builder报告收到卡片前已备份并修改，之后卡片validate/render及admission复验通过。不能把写后验证描述为写前验证。

实际修改限于原授权S00文档范围：三份候选与对应原字节备份；源文件、产品代码和review报告未变。备份摘要与独立审查绑定一致。此偏差不产生新的用户业务裁定或验收通过证据。

根因：主代理把补充指令发送与卡片准备顺序倒置。预防：后续修复卡片必须先生成并validate/render，再发委派。历史时序不可修复；保留此证据，由最终独立review核查实际差异、备份和内容，限制“所有治理流程通过”的声明。
