## 1. 目标与范围

目标：在不破坏现有仪表盘、图表、查询、权限及导出行为的前提下，分批交付八项增强能力，做到每片可独立构建、验证、回滚，并具有需求—代码—测试—证据的双向追溯。

| ID | 功能目标 | 最小可验证业务结果 |
|---|---|---|
| F01 | 图表过滤器复制与粘贴 | 从源图表复制过滤条件，在目标图表合法应用并反馈不兼容情况 |
| F02 | 移动端表格全屏 | 移动端进入表格全屏、横向浏览、退出返回原报告 |
| F03 | 表格明细数据导出 | 在权限及数据约束下导出表格明细，结果与当前业务规则一致 |
| F04 | 查询组件可选值过滤 | 配置查询选项过滤条件，并在查询时生效 |
| F05 | 透视表按列设置格式 | 可对维度/指标目标列设置并正确呈现格式与枚举值 |
| F06 | 多字段拖拽至维度/指标 | 多选字段并拖入指定区域，保持字段顺序与配置一致 |
| F07 | 枚举选项上限及超限处理 | 默认最多展示 5000 项；超限时可搜索/输入或自定义值（最终行为待 V1.0 核对） |
| F08 | 透视表自定义行汇总计算 | 配置计算表达式并随数据与筛选变化正确重算 |

**明确非目标**：跨功能冲突检测（此前明确暂不实施）；未经授权的系统性重构；未列入基线的产品功能扩展。

## 2. 分片原则

- **Vertical Slice**：每片包含必要的 UI、状态/接口、校验、测试、可观察性与文档；不以“只完成前端”视为交付。
- **最小变更**：优先复用现有过滤器、导出、查询、透视表及字段拖拽组件；先验证现状再决定是否新增接口。
- **可验证**：每片绑定具体场景、正反例、测试数据和运行证据。
- **依赖先行**：共用数据模型/权限/配置持久化契约先确认；功能间只建立有证据的依赖，不臆造强耦合。
- **分片完成 ≠ 功能完成**：只有全部业务规则、异常场景、回归项通过，才可宣布 Fxx 完成。

## 5. 质量要求与验收门槛

### 5.1 功能正确性
- 每条 V1.0 验收条件建立 `AC-Fxx-nnn`，每项至少一个可执行测试或人工验证步骤；不得以原始需求替代最终 V1.0。
- 正常、边界、异常、无权限、空数据、保存重载、刷新、历史配置兼容均须按适用性覆盖。
- F03 导出数据不得绕过行列级权限和脱敏；F08 汇总结果应与已确认的计算语义一致。
- 对原需求中“5000”“3 秒”等数值，先核对 V1.0 是否保留，再设为强制阈值。

### 5.2 工程质量
- 改动遵循现有架构与代码风格；公共能力优先复用，禁止无证据的大范围重构。
- 新增/修改逻辑具备自动化单元测试；关键跨模块路径有集成测试；核心用户路径有 E2E 或可复现手工测试。
- CI 构建、静态检查、相关自动化测试全部通过；**不得使用跳过测试的构建作为验收证据**。
- 对高风险计算、导出、权限路径执行独立验证；缺陷修复后至少回归受影响场景和依赖场景，避免无差别全量重测。

### 5.3 安全、性能与兼容性
- 权限控制在服务端执行；对用户输入、过滤表达式、计算表达式进行校验；导出遵循敏感信息治理。
- 大量枚举值、宽表移动端渲染、大数据导出和透视表重算分别建立可重复性能基准；未冻结阈值时先记录基线，不虚构 SLA。
- 兼容既有仪表盘/报告配置及数据模型；迁移必须可回滚；避免旧图表行为回归。
- 日志不包含敏感过滤值或导出内容；关键失败应有可诊断信息。

### 5.4 发布 Stop Gate
以下任一情况不得宣布完成：需求基线未核对；关键验收未覆盖；权限/数据正确性存在高严重度缺陷；构建或必需测试失败；回滚不可行；独立验证结论缺失。

## 6. 每片交付物（Definition of Done）

1. `Slice Contract`：目标、非目标、接口/状态、规则引用、AC 引用及风险。
2. 代码与配置变更：可审查的最小差异，附影响说明。
3. 验证资产：测试代码、数据夹具、运行命令、环境版本与结果。
4. 证据：测试报告、关键 UI 截图/录屏（适用时）、失败/修复记录。
5. `Closeout`：完成项、未完成项、遗留风险、回滚方式、独立复核结论。
